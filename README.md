# 한솔 지식창

HTML/CSS/JavaScript로 만든 개인 지식 메신저입니다. Firebase Firestore를 통해 지식·할 일·임시 계정 정보가 컴퓨터 간 동기화됩니다.

공개 사이트: https://hansol941201.github.io/hansol-knowledge/

## 바로 확인

`index.html`을 더블클릭하면 브라우저에서 UI와 저장·검색 기능을 확인할 수 있습니다.

## Windows 앱 실행

1. Node.js 설치
2. 이 폴더에서 `npm install`
3. `npm start`

Windows 단독 실행 파일은 `npm run pack`으로 생성합니다.
### 실행 파일 내려받기

로그인 없이 아래 주소에서 바로 받을 수 있습니다(항상 최신 빌드).

**https://github.com/hansol941201/hansol-knowledge/releases/latest/download/hansol-knowledge.exe**

main 에 푸시할 때마다 자동으로 빌드해서 `latest` 릴리스로 올립니다.

앱은 실행할 때 배포된 사이트(https://hansol941201.github.io/hansol-knowledge/)를 직접 띄웁니다.
그래서 사이트를 고치면 앱을 다시 받지 않아도 바로 반영되고, 팝업과 웹사이트가 같은 주소·같은
저장 공간·같은 Firebase 문서를 씁니다. 인터넷이 안 되면 실행 파일에 들어 있는 사본으로 열리고,
연결이 돌아온 뒤 팝업을 다시 열면 최신 사이트로 복귀합니다.

### 팝업 저장 명령어

팝업에 아래처럼 입력하면 자동으로 분류해 저장하고, 같은 Firebase 문서를 쓰는 웹사이트에
새로고침 없이 바로 나타납니다.

| 입력 | 저장 위치 | 저장 후 안내 |
| --- | --- | --- |
| `할일 내용` / `할 일 내용` | `todos` | `✓ 할 일 저장 및 연동 완료` |
| `기록 내용` / `기억 내용` | `memories` | `✓ 기록 저장 및 연동 완료` |
| `지식 제목 \| 내용` | `knowledge` | `✓ 지식 저장 및 연동 완료` |
| 그 외 일반 문장 | 저장하지 않음 (검색만) | 찾은 결과를 보여 줍니다 |

- `할일` / `기억`만 입력하면 저장하지 않고 목록만 보여 줍니다.
- 명령어를 붙이지 않은 입력은 검색입니다. 기억 저장소에는 `기억 …` / `기록 …` 으로
  입력했을 때만 들어갑니다.
- 항목마다 고유 ID, 종류(`type`), 원문(`raw`), 생성 시각(`createdAt`), 수정 시각(`updatedAt`),
  입력 출처(`source`)를 함께 저장합니다.
- `sortIntoCollections()` 가 배열마다 자기 종류만 남깁니다. 예전 버전이 기억을 `todos` 에
  넣어 둔 경우처럼 잘못 들어간 항목은 화면에서 숨기지 않고 제 배열로 옮깁니다.
- 인터넷이 끊기면 로컬에 먼저 저장하고, 연결이 복구되면 밀린 항목을 자동으로 올립니다.
- 동기화는 항상 ID 기준 병합입니다. 다른 기기의 자료를 덮어쓰거나 지우지 않습니다.
- 삭제는 삭제 표시로 남겨 두어 다른 기기와 합칠 때 되살아나지 않습니다.

### 저장 경로

팝업이든 사이트 화면이든 저장은 아래 공통 함수만 거칩니다. 같은 배열, 같은 localStorage 키,
같은 Firebase 문서(`shared/state`)를 씁니다.

| 함수 | 하는 일 |
| --- | --- |
| `createTodo(text, source)` | `todos` 배열에 항목 생성 |
| `createMemory(text, source)` | `memories` 배열에 항목 생성 |
| `createKnowledge(title, answer, options)` | `knowledge` 배열에 항목 생성 |
| `saveLocalState()` | 네 배열을 localStorage 에 저장 |
| `saveCloudState({ verifyIds })` | Firebase 에 ID 기준 병합 저장 후, 서버에서 문서를 다시 읽어 확인 |

`commitEntry()` 가 이 순서를 강제합니다:
배열 추가 → `saveLocalState()` → 화면 다시 표시 → `saveCloudState()` → **저장된 문서 확인** →
확인된 경우에만 `✓ … 저장 및 연동 완료`, 아니면 `로컬 저장 완료·클라우드 연동 대기 중`.
`실시간 연동 중` 표시만으로 성공 처리하지 않습니다.

협력업체 카드에는 업체명이 들어간 할 일·기억이 「관련 기록」으로 함께 표시됩니다.

바로 올리지 못한 항목은 `로컬 저장 완료·클라우드 연동 대기 중` 으로 두었다가, 자동 재전송으로
올라가면 그 말풍선을 `✓ … 저장 및 연동 완료` 로 바꿉니다.

### 초기화

상단 **⟳ 초기화** 버튼에서 두 가지를 할 수 있습니다. 먼저 JSON 백업을 받아 두세요.

- **이 컴퓨터만 초기화** — 이 컴퓨터의 사본만 지웁니다. 클라우드 자료는 그대로라 다시 내려받습니다.
- **전체 삭제** — 모든 기기에서 지웁니다. `삭제` 라고 입력해야 눌립니다.
  문서를 비우는 게 아니라 삭제 표시를 남깁니다. 그냥 비우면 다른 기기가 갖고 있던 사본을
  다시 올려서 되살아나기 때문입니다.

### 화면 구성

왼쪽 사이드바(대시보드 · 내 지식 · 할 일 · 기억 · 특허 · 협력업체 · 계정 · 연락처 · 업무지식)와
중앙 콘텐츠 2단입니다.

대시보드는 **자주 가는 사이트 · 오늘의 할 일 · 일정** 세 가지만 보여 줍니다.
지식 목록은 사이드바 메뉴로 들어가서 봅니다.

- **즐겨찾기(앱 런처)** — 검색창 위에 이미지 카드로 놓입니다. 카드를 누르면 새 탭으로 열립니다.
  대표 이미지는 PC 에서 올리고(PNG · JPG · WEBP), 채우기(cover) / 맞추기(contain) 중 고릅니다.
  이미지는 긴 변 420px 로 줄여 Data URL 로 저장하므로 동기화 문서 용량을 넘기지 않습니다.
  이미지가 없으면 이름 앞글자 placeholder 를 보여 줍니다. 드래그로 순서를 바꾸고 그 순서도 저장합니다.
  기본 7개는 해당 id 가 아예 없을 때만 만들어지므로, 지운 것이 되살아나지 않습니다.
- **오늘의 할 일 / 일정** — 아래쪽 2열에 같은 폭으로 놓입니다.
- **일정** — 월 달력입니다. 일정이 있는 날에는 점이 찍히고, 날짜를 누르면 그 날 일정이
  아래에 나옵니다. 오늘·내일에만 배지를 붙입니다. 날짜·일정명·시간(선택)·메모(선택)를
  저장하며, 저장하면 그 날짜로 달력이 이동합니다.
- 카드를 누르면 상세 보기가 열립니다. **＋ 지식 추가** 는 기억·할 일·업무지식·연락처·계정을
  고르는 창을 띄웁니다.

### 긴 기록 AI 검색

검색창 Enter/검색 버튼과 팝업 질문은 서버에서 현재 기록을 읽어 답합니다. `search-rules.js`는 기존 자료 목록/자동완성용이며 AI 검색을 대신하지 않습니다. 서버가 없거나 동기화 확인에 실패하면 연결/저장 오류를 표시하고 답변을 지어내지 않습니다.

- 원문을 Q&A로 바꾸거나 유사어를 등록할 필요가 없습니다. 지식 본문이나 기록에 그대로 붙여넣습니다.
- Firebase ID 토큰을 서버에서 검증하며 기존 소유자 UID만 접근할 수 있습니다. 계정 금고와 비밀번호는 AI 입력에서 제외합니다. 기존 특허/기본 협력업체/계정 목록 검색은 그대로 제공되며 AI 근거는 Firestore에 저장된 지식·기억·할 일·일정·업체 수정 기록입니다.
- 문단/문장 경계에서 최대 1,200자, 180자 중첩으로 **전체 본문**을 분할합니다. 현재 제목과 본문 해시가 일치하는 임베딩만 재사용합니다. 수정 전 `raw` 사본은 색인하지 않고 삭제 표시는 제외합니다.
- 실제 OpenAI 임베딩 + 문자 2/3-gram BM25 + 순위 융합으로 검색하고 인접 문맥을 보충합니다. 모델이 짧은 답변과 원문 인용을 생성합니다. 인용의 실제 부분문자열 검사와 별도 근거 검증을 통과해야 표시합니다. 원문 속 지시문은 신뢰하지 않는 데이터로 취급합니다.
- 답변은 캐시하지 않습니다. 서버는 답변 직전에 현재 기록 버전을 재확인하며, 화면도 자료 변경 시 기존 답변을 무효화합니다. 다음 질문 때 추가/수정 내용을 색인하고 삭제 문맥을 후보에서 제외합니다. 비활성 임베딩 캐시는 원문을 포함하지 않고 TTL로 정리됩니다.
- 로컬은 기존 localStorage와 IndexedDB를 사용합니다. 한쪽 저장 공간이 부족하면 다른 저장소를 사용하고 둘 다 실패하면 오류를 표시합니다.
- 클라우드는 작은 기존 문서를 그대로 읽고, 600 KB 이상부터 UTF-8 기준 최대 180 KB 조각으로 나눕니다. 조각과 참조 목록을 한 트랜잭션으로 저장하고 SHA-256 및 실제 서버 저장 내용을 확인합니다. 원문 중간/끝을 자르지 않습니다.
- 현재 **전체 동기화 상태 JSON 한도는 6,000,000바이트**입니다. 중복 `raw`/`text`, 이미지, 삭제 표시 등 모든 저장 필드가 포함되므로 입력 가능한 순수 글자 수와 다릅니다. 안전한 트랜잭션 요청 한도는 8 MB, 검색은 최대 12,000문맥이며 초과 시 명시적으로 실패합니다. 저장 한도 초과분은 클라우드에 저장되지 않으며 기기 저장 상태와 JSON 백업을 확인해야 합니다.
- 처음 분할 저장된 뒤에는 구버전 클라이언트의 단일 문서 덮어쓰기를 보안 규칙이 거부합니다. 다른 기기도 최신 사이트를 다시 열어야 합니다. 기존 ID 병합/삭제 표시/계정 암호화 방식은 유지합니다. 분할 자료가 생긴 후 예전 프런트엔드나 보안 규칙으로 롤백하지 마세요.

#### 최초 서버 연결

현재 프로젝트는 `.firebaserc`의 `hansol-knowledge-941201`, 지역은 `asia-northeast3`입니다. GitHub Pages는 그대로 사용하고 AI만 Firebase Functions에서 실행합니다.

1. `npm ci`, `npm ci --prefix functions`를 실행합니다(Node 22).
2. `npx firebase login --interactive`로 프로젝트 관리 계정에 로그인합니다.
3. `node tools/firebase-status.cjs`로 프로젝트·결제 연결·배포 권한·기존 함수·키 이름 존재 여부를 확인합니다. 키 값은 출력하지 않습니다.
4. Functions 배포에는 **Blaze** 결제 연결이 필요합니다. 새 요금제 전환은 사용자가 비용을 확인하고 결정해야 합니다. Functions/빌드/Artifact Registry/Firestore 읽기·쓰기·TTL 삭제/Secret Manager와 OpenAI API 사용량이 과금 대상입니다. 무료 할당량이 있어도 전체 무료나 예산 상한을 보장하지 않습니다. API 사용료는 ChatGPT 구독과 별개입니다.
5. 키가 없다면 [OpenAI API 키 페이지](https://platform.openai.com/api-keys)에서 해당 프로젝트 키를 만듭니다. 결제/사용량 한도를 확인한 뒤 `pwsh -File tools/set-openai-secret.ps1`의 **숨김 입력**에 붙여넣습니다. 채팅·소스·`.env`에 키를 넣지 않습니다. 이 스크립트는 stdin으로 `firebase functions:secrets:set OPENAI_API_KEY`에 전달하며 키 파일을 만들지 않습니다.
6. `functions/.env.example`의 공개 설정만 필요시 `functions/.env.hansol-knowledge-941201`에 복사합니다. 기본 UID/출처/모델은 코드에 설정돼 있습니다.
7. `npx firebase deploy --only firestore:rules,firestore:indexes,functions:knowledge-ai --project hansol-knowledge-941201`로 배포합니다. **규칙 배포를 먼저 완료한 뒤 새 프런트엔드를 공개**합니다. 배포 전 기존 자료를 JSON으로 백업합니다.
8. 함수 URL이 `ai-config.js`와 같은지 확인하고 기존 방식대로 `main`을 GitHub에 푸시합니다. Pages와 Windows 빌드가 이를 반영합니다.
9. 사이트 동기화 로그인 후 첫 질문을 실행하면 기존 전체 자료의 임베딩을 생성합니다. 처음에는 시간이 걸릴 수 있고 중간 실패 시 완료로 표시하지 않습니다. 다음 요청은 생성 완료된 임베딩부터 재사용합니다.

`OPENAI_API_KEY`는 Firebase Secret Manager에서만 관리합니다. `ALLOWED_UID`는 기존 보안 규칙 UID와 일치해야 하며 임의의 로그인 사용자로 권한을 넓히지 않습니다. `ALLOWED_ORIGIN`은 GitHub Pages의 origin(경로 제외)입니다. `ANSWER_MODEL`, `EMBEDDING_MODEL` 변경 시 실제 질문 검증을 다시 실행해야 합니다.

#### 검증 구분

`npm run test:ai`는 원문 분할/복원/한도, 전체 문맥 범위, 추가·수정·삭제, 인용 검사, 브라우저 저장·화면·오류 표시를 검증합니다. 브라우저 테스트의 서버 응답과 단위 테스트 벡터는 명시적인 대역이므로 **실제 AI 품질 검증이 아닙니다**.

`npm run test:live --prefix functions`는 실제 API 키가 있는 프로세스에서만 실행됩니다. 긴 혼합 기록의 앞·중간·끝, 제시된 현장 상태 4개 질문, 유사 표현·붙여쓰기·오타, 추가·수정·삭제, 근거 없음, 충돌, 지시문 삽입을 실제 모델로 검사합니다. 키가 없으면 실패 종료하며 가짜 성공을 반환하지 않습니다. 실제 배포된 인증/저장/사이트 연결 검증도 별도로 수행해야 합니다.

공식 기준: [Firestore 저장 한도](https://firebase.google.com/docs/firestore/quotas), [Firebase 서버 비밀값](https://firebase.google.com/docs/functions/config-env), [OpenAI 임베딩](https://developers.openai.com/api/docs/guides/embeddings), [구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs).


엑셀은 머리글 없이 `등록번호 · (빈칸) · 업체 · 공법명 · 명칭 · 명칭(보조)` 순서로 봅니다.
이미 들어 있는 번호와, 등록번호가 없는 행(공법 이름만 적힌 행)은 건너뜁니다.
여러 번 돌려도 중복되지 않습니다.

## 동작 확인

```bash
npm install
npm test
```

- `test/reset-check.mjs` — 초기화 버튼(백업·이 컴퓨터만·전체 삭제)과, 뒤늦게 올라간 항목의
  안내 문구가 완료로 바뀌는지 점검합니다.
- `test/shortcut-check.mjs` — 기본 7개 · 이미지 등록/미리보기/맞춤 방식 · 순서 변경 ·
  새로고침 유지 · 지운 기본값 복구 방지 · 다른 자료 보호를 점검합니다.
- `test/dashboard-check.mjs` — 대시보드가 바로가기·할 일·일정 세 가지만 보여 주는지,
  일정 추가·수정·삭제·정렬·배지·저장이 되는지 점검합니다.
- `test/layout-check.mjs` — 사이드바 2단 레이아웃, 자주 가는 사이트 CRUD, 할 일·기억 저장 분리,
  검색 시 영역 숨김, 카드 상세, 1440/1366/1024px 반응형을 점검합니다.
- `test/ui-check.mjs` — 할 일·기억 저장 분리, 검색어 형광펜, 검색 중 할 일 목록 숨김,
  결과 카드 글자 크기를 점검합니다.
- `test/entry-check.mjs` — 팝업 입력이 배열 · localStorage · Firebase 문서까지 실제로 들어가는지,
  저장 확인에 실패하면 완료로 표시하지 않는지 점검합니다.
- `test/sync-check.mjs` — Firebase 대역(`test/fake-firebase.js`)을 끼운 브라우저 두 탭으로 팝업 ↔ 사이트
  실시간 연동, 오프라인 보관 후 자동 업로드, ID 기준 병합, 구버전 클라이언트와 섞였을 때의 자동 복구,
  기억 저장소 화면 크기와 날짜 표기를 점검합니다.
- `test/offline-check.mjs` — Firebase 가 아예 안 붙거나 동기화 로그인이 안 된 상태에서도
  팝업 저장과 사이트 표시가 정상인지 점검합니다.

동기화 PIN 창은 언제든 닫을 수 있습니다. 닫아도 저장은 이 컴퓨터에 계속 쌓이고,
상단 연동 상태 배지를 누르면 다시 로그인 창을 열 수 있습니다.
